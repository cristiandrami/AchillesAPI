Testa un'API in cinque passaggi

Carica lo Swagger, indica l'indirizzo dell'API, configura gli utenti di test, scegli le verifiche e analizza le evidenze. Gli stessi passaggi valgono per il laboratorio e per una vera API autorizzata.

Pronto. Inizia caricando uno Swagger/OpenAPI.
1

Carica la specifica OpenAPI

È il file .json/.yaml fornito dal proprietario dell'API, oppure scaricato dal suo endpoint OpenAPI. Non è un file di configurazione AchillesAPI.

Nessuna specifica caricata.
2

Imposta il target e lo scope

Il Base URL è l'indirizzo del server che vuoi testare. L'host autorizzato deve corrispondere esattamente al server. Il tool non prova indirizzi esterni senza conferma.

Per un'API aziendale usa HTTPS e inserisci solo hostname e URL presenti nell'autorizzazione del penetration test.

3

Configura utenti, ruoli e credenziali

Il file auth.yaml definisce come autenticarsi, senza contenere password o token. I valori si inseriscono sotto e vengono passati soltanto al processo del test, senza salvarli nel report.

Nessuna autenticazione configurata: puoi comunque fare un piano offline o GET anonime.
Tipi supportati: Bearer, API key, Basic, cookie, OAuth2 client credentials e login JSON. Le credenziali vengono richieste solo se presenti nel file.
4

Scegli le verifiche

Ogni strumento mostra cosa richiede e se invia traffico. Il piano offline è il primo passaggio consigliato. I workflow di scrittura richiedono manifest e approvazione aggiuntiva.

PROCEDURA GUIDATA · SOLO SE VUOI TESTARE POST / PATCH / DELETE

Crea un test di sicurezza che usa risorse temporanee

Non devi scrivere codice o YAML. Rispondi alle domande qui sotto: alla fine AchillesAPI prepara il file tecnico per te. Questa procedura non contatta l'API e non modifica dati.

1 di 4 · Scegli le operazioni

1 Quale risorsa vuoi testare?

Troviamo nello Swagger un'operazione di creazione, una di lettura e una di cancellazione. Questa scelta serve a creare e ripulire solo oggetti temporanei.

Carica uno Swagger nel passaggio 1 della pagina, poi torna qui.

2 Con quali utenti esegui il test?

Scegli chi può creare la risorsa. Il secondo utente serve per controllare se riesce a leggere una risorsa che non gli appartiene.

Se non conosci questa regola, togli la spunta: il tool non può dedurla dallo Swagger.

3 Quali dati temporanei deve creare AchillesAPI?

Compila le proprietà che lo Swagger richiede per creare una risorsa. Sono dati fittizi che dovranno essere eliminabili. Un campo di testo viene usato per verificare che la risorsa sia stata creata proprio da questo test.

4 Come riconosci la risorsa nella risposta dell'API?

Dopo una POST, molte API restituiscono un oggetto JSON con un identificativo. Es.: {"id":"abc123","name":"prova"}. Qui devi indicare quale proprietà contiene l'ID. Non è il valore dell'ID: è solo il nome della proprietà (es. id, projectId).

Opzioni avanzate · Visualizza o modifica manualmente il file YAML

Crea il manifest delle risorse di test

Per i soli test di lettura (GET) salta questa procedura. Un manifest (es. resources.yaml) descrive quali risorse temporanee possono essere create, come ritrovarle tramite ID, quali identità confrontare e come cancellarle. È necessario solo per test con scritture POST/PATCH/DELETE. Il generatore non contatta l'API.

Importa prima uno Swagger (passaggio 1), poi cerca possibili workflow.
Non ancora generato: nessuna operazione di scrittura è autorizzata.

Se Swagger non dichiara POST, GET per ID e DELETE, non è possibile costruire un ciclo disposable sicuro automaticamente. In questo caso crea il manifest manualmente, usando gli endpoint reali e una procedura di cleanup approvata.
