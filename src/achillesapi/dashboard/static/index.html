3

Configura utenti, ruoli e credenziali

Il file auth.yaml definisce come autenticarsi, Puoi inserire i token direttamente nel file con token:, senza variabili ambiente. Conserva auth.yaml in modo riservato: contiene segreti in chiaro.

Nessuna autenticazione configurata: puoi comunque fare un piano offline o GET anonime.
Tipi supportati: Bearer, API key, Basic, cookie, OAuth2 client credentials, refresh token, Authorization Code con PKCE esplicito e login JSON. Per OIDC fornisci URL token e credenziali del provider già autorizzati; la dashboard non effettua il login interattivo. Se usi token inline, non sono richiesti altri valori nel terminale.

Configurazione accesso e login (OAuth2/OIDC)

Controlla gli scope e i metodi di autenticazione documentati nello Swagger e, facoltativamente, il file JSON di discovery del provider. Analisi offline: non effettua il login.

1 di 4 · Scegli le operazioni

1 Quale risorsa vuoi testare?

Troviamo nello Swagger un'operazione di creazione, una di lettura e una di cancellazione. Questa scelta serve a creare e ripulire solo oggetti temporanei.

Carica uno Swagger nel passaggio 1 della pagina, poi torna qui.

2 Con quali utenti esegui il test?

Scegli chi può creare la risorsa. Il secondo utente serve per controllare se riesce a leggere una risorsa che non gli appartiene.

Se non conosci questa regola, togli la spunta: il tool non può dedurla dallo Swagger.

3 Quali dati temporanei deve creare AchillesAPI?

Compila le proprietà che lo Swagger richiede per creare una risorsa. Sono dati fittizi che dovranno essere eliminabili. Un campo di testo viene usato per verificare che la risorsa sia stata creata proprio da questo test.

Per verificare campi modificabili o funzioni riservate, configura i controlli dedicati: Body PATCH e Mass Assignment · Operazioni riservate (BFLA) ·

4 Come riconosci la risorsa nella risposta dell'API?

Dopo una POST, molte API restituiscono un oggetto JSON con un identificativo. Es.: {"id":"abc123","name":"prova"}. Qui devi indicare quale proprietà contiene l'ID. Non è il valore dell'ID: è solo il nome della proprietà (es. id, projectId).

Lo Swagger non dice dove si trova l’ID? Prova una creazione verificataOpzionale · POST + GET + DELETE reali

AchillesAPI può creare UNA risorsa temporanea autorizzata, leggere la risposta POST per trovare l’ID, verificare con GET e provare DELETE. La prova NON viene avviata automaticamente. Se l’ID manca, GET fallisce o la risorsa non può essere verificata, potrebbe essere necessaria la cancellazione manuale.
